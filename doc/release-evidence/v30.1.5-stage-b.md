# v30.1.5 Stage B implementation checkpoint

This is focused local evidence for the source recorded with this file, not
release approval, full CI evidence, or completion of roadmap issue #52.

## Changes

- Bounded wallet-only claim input and legacy reserve enumeration, followed by
  one exact chain-coin checkpoint per selection attempt.
- Selection snapshot, exact output/time, and policy generations carried through
  signing and final wallet publication; no submission-time AvailableCoins scan.
- Worker-refreshed, generation-checked GUI reserve cache; nonblocking status
  reads and staking disable; unavailable reserve details are not rendered as zero.
- Ownership-independent proof/anchor indexing and bounded claim-source work.

## Reuse the retained build

The retained build is `~/.cache/blackcoin-builds/v3015-claim-lock-stage-b`.
On this Mac, select the current Command Line Tools and obtain static liboqs
link dependencies from current pkg-config metadata:

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools make -C src -j6 \
  LIBOQS_LIBS="$(/opt/homebrew/bin/pkg-config --static --libs liboqs)" \
  test/test_blackcoin
```

Do not clean this build for an individual failure. Compile its affected objects,
relink the affected target, and rerun the smallest relevant test filter. Quote
Boost test filters containing `*` when using zsh. The original local link
configuration referenced removed OpenSSL 3.6.2 and an older Xcode linker that
could not read the current macOS SDK; neither problem required source recompilation.

No full CI, release packaging, signing/tag publication, or deployment run was
started for this checkpoint. Final release still requires the outstanding
