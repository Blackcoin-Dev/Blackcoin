## One-shot recovery contract

The recovery accepts only a manual dispatch by Blackcoin-Dev at the exact signed
control tag, with explicit recovery acknowledgement and the existing final-release
environment acknowledgement. The control commit must directly descend from the
frozen source and modify only the enumerated publication-control files.
Local SSH verification and GitHub verification bind both source and control.

A fresh developer-authenticated immutable-configuration observation is recorded
in a receipt bound to the source, final tag object, source run/attempt, control
commit and control tag. The allowlisted release key signs that receipt using SSH
namespace `blackcoin-release-configuration`. Its maximum lifetime is one hour.
The receipt and signature are non-secret dispatch inputs; no private key or
long-lived credential is uploaded. It is checked before artifact processing and
again immediately before draft creation and publication. This narrowly replaces
only the integration-token-inaccessible configuration read.

The runner downloads the six existing artifact archives, checks their pinned
digests, and extracts them safely. Frozen-source generators reproduce the original
metadata using the original source date and run ID. Existing GitHub attestations
must bind the exact 19-subject set; the checksum file yields 20 final assets.
No build, functional test suite, or new attestation is run.

Publication fails closed unless the release is absent, the exact draft body and
all uploaded asset names/sizes/digests match, and the fresh receipt remains valid.
After publication, the release must be immutable, non-draft, non-prerelease,
latest, and still bound to the untouched final tag. A failed upload does not
authorize automatic deletion or replacement of an existing draft or release.
Remove the temporary environment admission after successful publication; preserve
the signed control tag as the immutable recovery audit record.
